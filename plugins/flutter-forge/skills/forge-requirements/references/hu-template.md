# Default user story template

Projects can replace it with `requirements.template` in the profile. Keep the section numbers
when adapting it, because `hu-to-brief.md` maps sections by number. Write the story in
`requirements.language`.

```markdown
# HU-<id> · <Feature name>

| Field | Value |
|---|---|
| Module / epic | <module> |
| Platform | App (mobile) |
| Priority | <must / should / could> |
| Status | Draft (generated by flutter-forge — pending approval) |
| Design | <Figma link or "none yet"> |

## 1. Story and purpose
**As** <role>, **I want** <capability>, **so that** <benefit>.

Objective: <one sentence on the business outcome>.

INVEST check: Independent ✓/✗ · Negotiable ✓ · Valuable ✓ · Estimable ✓/✗ · Small ✓/✗ · Testable ✓
<If Small ✗: proposed split into stories A, B, C.>

## 2. Use cases
- **Happy path:** 1. … 2. … 3. …
- **Alternative paths:** …
- **Contingencies:** no connection · session expired · server error · <domain-specific>

## 3. Business rules and validations
| # | Rule | Value | Source | Message shown |
|---|---|---|---|---|
| R-1 | Minimum amount | [TBD] | Business | "<exact copy>" |
| R-2 | Default currency | [TBD] | | — |

Permissions and roles: <who can and cannot>.
Traceability: <does the action need an audit trail, receipts, notifications?>

## 4. Acceptance criteria
- **AC-1** — Given <context>, when <action>, then <observable outcome with values>.
- **AC-2** — Given …
- **AC-n (edge)** — Given …

## 5. Screens, navigation and states
| Screen | Entry from | Exit to | States |
|---|---|---|---|
| <Screen A> | <origin + condition to show the entry> | <destination + parameters> | loading · empty · error (+retry policy) · success · validation |

- Live validation: <which fields, when>.
- Blocking vs interactive: <what stays usable while loading>.
- Premature exit: <confirmation dialog or none>.
- Non-functional: <optimistic UI, debounce, max latency before showing loading, offline behavior>.

## 6. Design references

## 7. Data and integration (to be confirmed by backend)

|---|---|---|
| <balance> | <backend> | <GET … or "unknown"> |

## 8. Security and privacy
- Sensitive data: <credentials | pii | financial | health | location> → masking rule (e.g. show last 4 digits).
- Never logged: <fields>.
- Re-authentication / confirmation before: <action> (biometrics, PIN, OTP?).
```
